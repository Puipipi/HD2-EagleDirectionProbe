## 最有价值的入口：每条活跃战备记录的类型与坐标

`sample_active`（1602 行）从 game.dll 相对位置 `0x33266B0` 取得管理器指针；
管理器 `+0x34` 为数量、`+0x78` 为数组指针，每条记录 64 字节。
读取数量上限为 512，检查短读、指针和非有限坐标。

记录中 `+0x0C` 为源码称作 `native_type_candidate` 的类型，`+0x10/+0x14/+0x18` 为位置 XYZ，
`+0x30/+0x34/+0x38` 为方向锚点 XYZ。读取器没有输出稳定的记录 ID 或逐条时间戳。
与旧 CT 手选槽不同，这是一条同时具有类型与位置的活跃记录入口。

`sample_comms`（1663 行）读取另一环形缓冲区中的 kind 20 通讯事件，
`attach_throwers`（1687 行）按 XY 各差不超过 0.05 m 匹配 owner；遇到不同 owner 歧义时不归属。
这仍是空间匹配，不是对象唯一 ID 关联，更不是飞机唯一 ID。

接入我们的模组时，可将类型记录与已有落地球位置做保守、唯一匹配，才替换 EAGLE ?；
近距离并发、重叠点、球弹跳、记录复用与不同类型歧义必须保留未知状态。
不应从数组下标、最近菜单选择或全世界弹药存在推断类型。

## 显示、方向、范围与清理

- **实心标记是屏幕矩形**：539 行创建 screen GUI，544 行将世界点投影到屏幕，
  404 行通过 Gui.rect/update_rect 绘制实心小方块。文字使用 Gui.text/update_text。
  没有 world GUI 或 Gui.triangle；不能拿它证明 1.10.0-rc1 世界三角面的材质/遮挡已实机可用。
  整体转用此路径会改变遮挡表现，不能直接当作用户默认关闭透视的替代实现。
- **方向来自锚点**：807 行 collect 使用落点减锚点；多数空袭再旋转 90 度形成横向投弹带。
  1–80 m 之外不采用该轴。它不读取实际飞鹰进场方向；我们的飞机轨迹、离场冻结轴仍有价值。
- **范围是基线参考**：目录区分单弹满伤、外缘与冲击波，并注明非击杀/安全边界。
  多枚投弹带长度按外径相接估算，不是实测散布；舰船升级状态没有由此可靠读出。
  110mm 不把球的位置当追踪目标。可以参考形状规则，不能直接标成精确攻击范围。
- **当前快照替代旧图形**：1999 行约 10 Hz 采样当前活跃记录；记录为空、读失败、任务切换、
  本地玩家生命周期变化时清理 HUD。GUI 图元复用 ID，缩减时删除多余对象，世界失效不调用旧析构句柄。
  活跃记录何时消失仍需实机观察；不应取代我们已按飞机退场确认的结束规则。

## 不照搬的开销与限制

- 838 行最多 16 个模型；第 17 个返回失败，随后清空当前参考。这不符合用户“不限制数量”的要求。
- 1278 行每帧重置 48 次高度采样预算，使用 0.5 m XY 网格缓存；1288 行 miss 缓存为 false。
  部分投掷弧裁剪还直接逐段射线。不能将这些预算套入我们的每帧两次全局预算。
- 屏幕标记每帧投影与更新，文本还有多次描边；真实字体 token 来自 HUD 数据，带默认字体降级。
  文字方案可作为后续更清晰标签的参考，但字体可用性、投影和每帧成本需要独立核查。
- 源码的 loader 版本条件、输入检测和全部启动逻辑不适合原样引入。只借鉴需要的入口和语义。
