# 1.10.0-rc5：类型确认先于首次范围显示

## 原因与行为

rc4 只对已经创建的地面指引开始识别类型。地面先按未知类型绘制 200×12 m 默认走廊，之后经过两次相隔至少 0.12 s 的唯一匹配，才得到真正战备类型并调整范围。5 Hz 查询意味着通常晚约 0.2–0.4 s；原设计没有协调首次显示与类型确认。

rc5 把识别提前到已经判定为投出的战备球的原有落地稳定阶段（0.35 s），复用同一原生读取器、5 Hz 频率、双快照与互相唯一的位置约束。正式创建落点指引时，只继承这个球本次稳定阶段的候选；不会用投掷者、全局最近战备或其他玩家的缓存猜类型。

若新指引尚未确认且读取器 READY、自适应范围开启，边框、地面三角与警戒光片暂缓最多 0.45 s。落点菱形、飞机旁箭头与天空方向箭头继续显示。等待期间不为默认宽度建立地形网格，确认后直接按对应参考范围采样，预算仍共享每帧两次。

读取失败、接口不支持或关闭自适应范围时不增加这项等待。空结果或歧义在窗口结束后恢复通用指引，避免永久不显示。若原生记录特别晚才出现，仍允许之后保守确认并适应；这项修复消除正常首次双快照的闪现，不承诺所有延迟都能预知。

飞行重新开始、稳定阶段被破坏、球在落地确认前超过 0.75 s 未观测时，清除临时候选并重新计稳定时间。代码审查复现了“预识别 500kg 后球消失 2 s，再于 3 m 外匹配空袭记录却继承旧类型”的路径，已新增先红后绿回归并修复。正式落地后已经确认的类型保留规则与原来相同。

## 验证与交付

新增 7 项回归：首次可见范围不先画默认、真实投掷在创建落点前完成类型匹配、旧指引退休后单位复用、四队友独立预识别、未落地查询长缺口丢弃旧候选、有界空/歧义回退并保留其他指引、读取失败回退及范围关闭不等待。其中部分场景合并在同一测试中。全套 179 项检查通过。

离线 1/4/8 路预热基准与 rc4 比较，驻留面数、原生更新数、5 Hz 快照数相同，测量窗口内没有额外地形查询或静态地面重建。Lua 时间存在运行波动，不据此声称实际 FPS 提升。多了落地前少量预查询，未提高频率、没有新增原生调用方式。

保留创建 XYZ / 更新 XZY、攻击来袭方向锁定、rc4 光片与真面边带、九项 MOM 保存、原退场生命周期；无 Runtime 依赖和活跃指引数量上限。六个资源编译及封装检查通过，原生地形两资源与稳定版 1.9.10 字节一致。沿用 GUID，手动导入，无自动部署。

实机请观察空袭、扫射和 500kg 第一次出现的范围；同时投掷时检查类型是否各自正确、失败时是否仍有通用指引，并确认攻击结束清理。此前保存的真填充开关保持原值。
