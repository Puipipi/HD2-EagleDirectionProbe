# 1.10.0-rc1：真正面填充测试候选

**2026-10-09 更正：用户实机确认开启后图形错位，关闭后恢复正常。**
本文原先的创建/更新坐标结论只核查了 Lua 包装层，漏掉共享后端的第二次 Y/Z 转换，结论错误。
完整路径需要创建传 XYZ、更新传 XZY；旧模拟测试也遗漏后端转换。
rc1/rc2 均包含该缺陷，请使用 [rc3 修复候选](display-fix-1.10.0-rc3.md)。以下保留核查历史，不能作为原坐标正确的证据。

2026-10-09。稳定版仍为 1.9.10。本版供手动导入，不自动部署，不依赖 HD2Runtime。

## 改动

- 飞鹰箭头及箭杆、天空竖直 →、地面三角、金色落点菱形、移动红色光片使用真实三角面。
- 白色走廊边框、尾迹、光片边缘和 EAGLE ? 文字仍使用线段，保留原样式与移动速度。
- 地面三角细分成五个面片，复用缓存高度；光片按左、中、右缓存高度分成两半。
  地形精度和全局每帧最多两次查询、0.5 ms 软预算不变。没有新增碰撞查询或活跃指引数量上限。
- 新增 MOM 选项“真正面填充（测试）”，本候选默认开启。MOM 保存选择，关闭恢复 1.9.10 线段填充。
  开启透视显示时回到线段；所需 API 缺失或发生 Lua 错误时也回退，不猜测 GUI 的透视参数。
- 三角对象复用 ID；几何不变时不更新，运动几何缓存约 20 Hz，飞机几何在姿态变化时更新。
  数量缩减时销毁多余三角，战备退场清空，关闭选项/深度切换时释放 GUI。
  世界失效后丢弃句柄，避免通过已消失的世界调用析构函数。

类型识别和攻击范围没有新增进展：仍显示 EAGLE ?，走廊不是测量伤害范围。

## 引擎接口证据

[Autodesk World 文档](https://help.autodesk.com/cloudhelp/ENU/Stingray-Help/lua_ref/obj_stingray_World.html)
提供世界空间 GUI；[Gui 文档](https://help.autodesk.com/cloudhelp/ENU/Stingray-Help/lua_ref/obj_stingray_Gui.html)
提供三角面的创建、更新与销毁。通用引擎文档只能提供接口线索，不能证明 HD2 的原生签名。

本次同时核查已安装模组源码、实际 Lua API 清单，以及既有的只读解码快照：

- 构建记录：helldivers2.exe SizeOfImage 60719104、时间戳 1790149348；与当前地形契约一致。
  解码代码段 SHA256：499e1b745d53560e33d4159715f443c52e98515dd35d10394e179d959b0af59c。
- World.create_world_gui 的 Lua 包装读取 world、Matrix4x4、两项比例；保留模式为默认。
  本版使用 `(world, Matrix4x4.identity(), 1, 1)`，没有额外材质、即时、阴影参数。
- Matrix4x4 注册表中核实 identity 的绑定；构造器仅在首次实际提交图形时调用。
- Gui.triangle 读取 GUI、三个顶点、层、颜色，返回整数 ID。
  HD2 的创建包装交换 Y/Z，更新包装直接使用 XYZ。已安装的屏幕 HUD 三角面源码也明确处理这一差异。
  rc1 模块创建时传 XZY，更新时传 XYZ；**此策略错误，rc3 已反转**。
  包装层后的共享原生顶点写入还会交换 Y/Z。两个方向的绕序用于从两侧观察。
- 清理使用 Gui.destroy_triangle 与 World.destroy_gui。模块加载/菜单回调不会创建原生图形。

新模块只调用引擎 Lua 显示 API，不引入直接地址调用、内存访问、FFI、游戏状态写入或 Runtime。
现有两个地形模块的原始字节不变。私有快照、反汇编和游戏二进制不随包发布。

**任务内仍未验证**：世界 GUI 的默认材质、裁剪、双面透明混合、遮挡、与脚本临时内存恢复的配合，
以及原生实际渲染性能。离线回放模拟的是已核查的参数语义，不能证明原生调用不会崩溃；pcall 只能捕获 Lua 错误。

## 离线验证

144 项检查，包含新增八项：真实面片覆盖、创建/更新坐标差异、反向绕序、ID 复用与缩减、非法顶点、
失效世界、菜单和透视切换清理、Lua 失败回退、140 fps 下的运动更新缓存，以及原查询预算。
四模式旧回放验证线段回退，真实 LuaJIT 编译门禁覆盖四个打包资源。

基准命令：

```powershell
python -B tests/offline/benchmark_render.py --baseline-ref v1.9.10 --solid-fill --repeats 3
```

140 fps 模拟循环，每组预热 600 帧，再测 280 帧，三次取中位数。原生渲染为模拟：

| 同时指引 | 旧/新 Lua ms/帧 | 旧/新分配 KB/帧 | 旧/新线段/帧 | 新三角更新/帧 |
| --- | --- | --- | --- | --- |
| 1 | 0.0584 / 0.0314 | 45.67 / 15.22 | 1181.7 / 244.2 | 72.3 |
| 4 | 0.1925 / 0.0806 | 171.35 / 48.71 | 4726.7 / 976.8 | 289.2 |
| 8 | 0.4790 / 0.2201 | 339.00 / 93.35 | 9453.3 / 1953.6 | 578.5 |

测量段均无地面静态重建或新增查询。线段和三角更新成本不能等价换算，表格不代表游戏 FPS 改善。

## 手动验收

1. 手动导入 `dist/HD2-EagleDirectionProbe-1.10.0-rc1.zip`，保留 1.9.10 供回退。
2. 普通任务投掷一枚飞鹰战备，侧看天空 → 和红光片、俯看地面三角；观察有无真正连续填充、
   闪烁、坐标错位或单侧不可见，确认远端坡面与原版贴地接近。
3. MOM 关闭/开启“真正面填充（测试）”，确认即刻切换且不留下旧面片；重启检查保存。
   开启透视应恢复线段，关闭后恢复面片。
4. 战备攻击结束、所有显示关闭、任务退出时检查无残留；多队友并发时比较帧率。
5. 出现异常可关闭真填充或重新导入 1.9.10。记录加载器日志中 `true fill` 行和任务截图。

安装包只包含封装资源与说明/封面，尚未自动导入正在运行的游戏。
