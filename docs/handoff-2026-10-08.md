# 1.8.1 接手记录

接手 dsh 的“飞鹰红战备来袭方向预测模组”会话，最后反馈为“飞鹰战备落到地面直接崩了”。
接手时已有未提交的 1.8.0 改动及其安装包；本次保留其判空和读/画排序，只修已复现缺陷。

## 已复现并修复

1. `build_geometry/add_strip` 的线段首元素为 `colour('ground')` 返回的引擎对象，
   `submit_geometry` 却使用 `colors[s[1]]`，其中表只含 `air` / `ground` 字符串键。
   因而地面颜色必为 nil。1.7.0 将其直接交给原生 `add_line`；1.8.0 则跳过线段。
   改为缓存字符串 `ground`，引擎对象只在提交当帧构造。
2. JSON 转义使用包含字面 NUL 的 Lua pattern，LuaJIT 5.1 报 `malformed pattern (missing ']')`。
   改为 `%c`，并用全部 0..31 控制字符、引号、反斜杠和中文做往返测试。
3. 构建和测试默认导入 `lupa.LuaRuntime`，当前环境实际选择 Lua 5.5，却声称验证 LuaJIT。
   相关入口改为显式 `lupa.luajit21`，门禁新增拒绝 Lua 5.4+ `<const>` 语法的回归测试。
4. `tests/offline/run_harness.py` 旧路径重复拼接模组目录；加载失败只打印而不失败退出。
   修正路径，加载失败抛错，回放出现 Lua 错误也使入口失败。

## 证据

- 新增 `tests/test_runtime.py`，先运行失败再修复。
- 日志回放修复前，LuaJIT 单机/查询丢帧/双机场景各有 67..70 次 JSON emit 错误。
- JSON 修复后、地面颜色修复前，140 fps 回放在三种场景均跳过 121422 条地面线段。
- 地面修复后要求 `skipped=0`，且真实 `add_line` 边界必须收到地面颜色、非空向量；检查 JSONL 样本。
- `python -m unittest discover -s tests -q`：68 项通过。
- `tests/offline/run_harness.py`：正常、查询丢帧、世界包装变化、双机四种模式 Lua 错误均为 0。
- `verify_shapes.py`：实际生成的端点图中找到闭合三角形。
- `verify_terrain.py`：平地高度差 0；合成坡地插值高度差 28.47 m；这是插值验证，不是真实地形查询。
- 构建四道门禁通过；包内源码与当前源码核对一致（声明行由封装工具统一换行）。

## 原生崩溃结论的限度

22:48:37 与 22:59:45 的两个 WER 转储都指向 `ntdll.dll+0x39463`，指令为
`inc dword ptr [rax+0x24]`，rax 为 0。仅凭这条指令不能判定是 Vector3、Color 或临时内存恢复导致。
后一会话最新探针状态为 `calls=0 / segments=0 / submits=0`，尚未发生任何地面绘制。
因此不能把两次崩溃都归因于同一绘制路径，也不能宣称全部原生崩溃已解决。

原会话宣称“绘制移出临时内存守卫就是根因修复”缺少直接证据。本次不再据此宣称成功；
保留 1.8.0 顺序以避免同时修改多个变量。可复现、可验证的缺陷是上述空颜色路径。

禁止复用首次异常调试器接入：已有项目记录表明接入会诱发退出。原始转储、私人日志保留本地。
